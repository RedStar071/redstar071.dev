# Design — RedStar

> Generated by `nuxt-frontend-design`. This file captures the _intent_ behind design decisions so future work stays cohesive across conversations, contributors, and skills. Compatible with the `@google/design.md` linter.
>
> **Front matter** holds machine-readable tokens (colors, typography, spacing, component surfaces). Prose below holds rationale, behavioral rules, and judgment. Tokens are normative; prose is context. Token refs use `{path.to.token}` (e.g. `{colors.primary}`).

## Aesthetic Direction

- **Theme**: custom, built for RedStar. No preset theme; it borrows structure from three reference sites and identity from the WolfStar brand.
- **Mode**: both, dark by default (`colorMode.preference: 'dark'`). Light mode reads like the avatar's own background: pale grey with red stars.
- **Vibe**: playful night-sky sticker book.
- **Influences**:
  - [bignut.zip](https://bignut.zip): Material 3 expressive bento cards (32px radius), shaped icon badges, lowercase conversational headings, segmented link rows, round tonal footer buttons, the wavy striped banner.
  - [pa.nley.contact](https://pa.nley.contact): the big "hi there! i'm / name" hero and a live Discord card.
  - [harlanzw.com](https://harlanzw.com): sticky blurred header with avatar and icon nav, mono metadata next to sans prose, inline coloured links in the bio, a quiet "latest writing" list.
  - RedStar's own identity: the WolfStar "Wolf Ember" red (`oklch(63% 0.2502 28.13)`, #FD171B), the chubby red stars around the GitHub avatar, the "⛧ RedStar ⛧" Discord name with symbols on both sides.
- **Design principle**: we prioritise personality over neutrality. When two options are equally usable, pick the one that looks like it belongs to RedStar (a star, a shape, the red) rather than the generic one.
- **Personality of motion**: springy and brief. Entrances rise 14px over 700ms on a Material 3 spatial spring; shapes spin half a symmetry step on hover; stars twinkle slowly. Nothing loops fast.

## Color Decisions

| Role     | Value                                   | Why                                                                                   |
| -------- | --------------------------------------- | ------------------------------------------------------------------------------------- |
| Primary  | Tailwind `red` (500 ≈ WolfStar #FD171B) | Tailwind's red-500 is within a hair of the WolfStar ember red, so no custom scale is needed |
| Neutral  | `night`, a custom scale at hue 255      | WolfStar's dark theme is navy-slate; a navy-tinted neutral makes the red read warmer  |
| Sticker  | red-300 fill with a red-500 stroke      | Copies the stars drawn around the avatar                                              |

- **Primary by surface**: text uses red-400 in dark mode and red-700 in light mode for contrast. Filled surfaces (solid buttons, solid badges, stars, banner stripes) always use red-500 so the brand red stays true.
- **Neutral tinting**: every grey carries a little navy (chroma 0.003–0.017), matching the WolfStar dashboard.
- **60-30-10 split**: about 60% night surfaces, 30% text and rows, 10% red (stripes, stars, CTAs, links).
- **Layering**: page (night-950) sits below bento cards (`bg-muted`, night-900), which sit below list rows (`bg-elevated`, night-800). Light mode: grey page, white cards, grey rows, the same layering bignut uses.

### Contrast & Accessibility

- **Body text contrast**: default text on night-950 is 15.4:1; muted text is 7.6:1 on the page and 5.8:1 on rows.
- **Primary text**: red-400 on night-950 is 6.7:1. In light mode, red-700 on white is 6.4:1.
- **Solid buttons**: night-900 text on red-500 is 4.6:1 in dark mode; white on red-700 passes in light mode.
- **Known risks**: `text-dimmed` (night-500) is 4.0:1 on the page, so it is never used for text a reader needs.

## Typography

| Role                  | Font             | Why                                                                                            |
| --------------------- | ---------------- | ---------------------------------------------------------------------------------------------- |
| Body (`--font-sans`)  | Google Sans Flex | bignut's typeface. It is variable and carries a roundness axis (ROND)                             |
| Display (`font-round`) | Google Sans Flex, `ROND 100`, weight 900 | Fully rounded terminals give headings the same soft, sticker-like shape as the stars |
| Mono (`--font-mono`)  | Google Sans Code | Harlan-style metadata (handles, dates, labels) from the same family as the sans                        |

- **Type system**: a fixed rem scale. The hero name goes from `text-6xl` to `text-9xl`, card titles are 28–32px at weight 500, and body text is 16–18px.
- **Voice in type**: headings and bullets are lowercase and conversational ("what i've made"). Proper nouns keep their capitals.
- **Font loading**: `@nuxt/fonts` self-hosts both families. The module is listed before `@nuxt/ui` in `nuxt.config.ts` so its options are only merged once; otherwise the ROND axis values are duplicated and Google Fonts rejects the request.

## Icons

- **Collection**: Material Symbols Rounded (`i-material-symbols-*-rounded`). Brand logos come from Simple Icons.
- **Why**: the rounded symbols match Material 3 expressive and bignut, and their soft ends match the star stickers.
- **Gotcha**: names that start with `light` clash with the `material-symbols-light` collection. Write those as `material-symbols:light-mode-outline-rounded`.
- **Color rule**: icons are monochrome and inherit text color. Red is reserved for badges, stars and interactive accents.

## Component Rules

- **BentoCard**: `bg-muted`, `rounded-2xl`, a ShapeBadge, then a lowercase h2 at 28–32px. The first card on a page gets the solid badge; every other card uses the tonal one.
- **ShapeBadge**: an M3 shape used as a mask (cookie, burst, flower, clover, sunny or star). On card hover the shape turns half a symmetry step (for example 20° for the 9-lobe cookie) while the icon stays upright.
- **LinkRow lists**: rows are `rounded-xs` inside a `rounded-lg` clipping list with a 2px gap. On hover or focus a row morphs to `rounded-md` and lifts one surface level. External rows show an outward arrow and screen-reader text saying the link opens in a new tab.
- **Buttons**: always pills. Pressing morphs them to `rounded-md` at 97% scale. Primary solid for the main call to action, `soft` for secondary actions inside cards, `ghost` or `subtle` for navigation.
- **Stars**: use `StarSticker` (sticker, solid or outline). Never draw a new star path; everything reuses `STAR_PATH` from `app/utils/shapes.ts`.
- **Live data**: Discord presence is fetched client-side from Lanyard. It shows a skeleton while loading and an inline retry on error, and it never blocks rendering.
- **Content-driven sections**: the writing nav link and the "latest writing" card only appear once `content/blog` has at least one post.

## Spatial & Motion

- **Spacing system**: Tailwind's 4px grid. Cards use 20–24px padding and 16px gaps. The hero-to-bento gap is 64–80px.
- **Radius scale**: `--ui-radius: 0.5rem` makes Nuxt UI's radius scale line up with Material 3 corners: xs 4, sm 8, md 12, lg 16, 2xl 32.
- **Easing**: `--ease-spatial` (a cubic-bezier with a slight overshoot) for movement, `--ease-effects` for color and radius changes.
- **Animation style**: `animate-rise` staggers entrances with `--i` (70ms each). `animate-twinkle` uses `--delay`. The banner stripes drift one wavelength (720px) every 36s, so the loop is seamless.
- **Reduced motion**: every animation uses the `motion-safe:` variant, and a global `prefers-reduced-motion` rule collapses the rest. Theme switching skips the circular view transition.

## Responsive Strategy

- **Approach**: mobile-first. The bento is one column below `lg` and two columns from `lg`. The grid must use `grid-cols-1` (`minmax(0, 1fr)`) and `min-w-0` columns; otherwise truncated rows push the track wider than the viewport.
- **Navigation adaptation**: header links become icon-only below `sm`, keeping their aria-labels.
- **Hero**: the name scales from 60px to 128px. On phones the banner hides its smaller stars.

## Voice & Tone

- **Headings**: lowercase and first person ("where to find me", "on discord right now").
- **Button labels**: short verbs ("say hi", "contact", "all projects", "try again").
- **Empty states**: say what's missing, then point somewhere useful ("nothing here yet", then a link to GitHub).

## Avoid

- Pure black or pure grey surfaces. Use the `night` scale.
- Drawing stars or shapes by hand in components. Reuse `STAR_PATH` and the `shape-*` utilities.
- Title Case headings in the playful sections.
- Shadows on dark cards. Depth comes from the surface layers.
- Red body text. Red is for accents, links and calls to action only.
- Placeholder or invented content (fake testimonials, stats, talks). Sections appear only when real content exists.

## Custom Utilities

| Class/Token                     | What it does                                                        | When to use                                   |
| ------------------------------- | ------------------------------------------------------------------- | --------------------------------------------- |
| `shape-cookie` … `shape-star`   | CSS mask with an M3 expressive shape (100×100 polar curve)          | Badges, avatar frames                         |
| `font-round`                    | `font-variation-settings: "ROND" 100`                               | Display headings and wordmarks                |
| `animate-rise` + `[--i:n]`      | Staggered spring entrance                                           | Hero pieces, cards, list items                |
| `animate-twinkle` + `[--delay]` | Slow scale/rotate pulse                                             | Star stickers only                            |
| `animate-drift`                 | Moves an element 720px left, looping                                | The hero stripe pattern                       |
| `--ease-spatial` / `--ease-effects` | M3 expressive spring approximations                             | Transitions (`ease-(--ease-spatial)`)         |
| `night-*` colors                | Navy-tinted neutral scale                                           | Registered as the Nuxt UI `neutral` color     |

## Design Decisions

- Dark is the default mode because all three references are dark-first and the stars read best on night navy. Light mode stays fully supported.
- The template's testimonials, FAQ, talks page, about page and sample blog posts were removed because none of them were RedStar's content.
- Discord presence details (activity names, rich presence lines) are shown as Discord publishes them through Lanyard.
